# MovScript Admin v2 本地模式设计

本文档专门定义 Admin v2 的本地 / 免费个人模式。它是默认 Basic Admin 体验，面向“我自己使用 MovScript，并且自己带一个 key”的用户。

本地模式不是完整后台的简化皮肤，而是一套独立的信息架构：只保留个人创作闭环所需的入口，把团队、治理、审计、租户、多 provider 策略等平台概念收进高级或云端/团队 profile。

## 1. 本地 / 免费个人模式的产品判断

本地 / 免费个人用户通常只有：

- 一个本机 owner
- 一个本地 workspace
- 一组或少数几组 provider key
- 更常见的是一个中转站 / 聚合站 key
- 一个主要目标：马上开始生成视频

因此本地 / 免费个人模式不应该默认展示：

- 用户与组织
- 审计日志
- 团队用量分析
- 多租户权限
- 云部署控制
- 全量 Provider Registry
- 全量 Model Catalog / Route Binding 编辑

这些能力仍然存在，但属于：

- 高级
- Agent 专注修复
- 团队/云端 profile
- Dev/Debug profile

### 1.1 与其他用户层的边界

| 用户类型 | Admin 策略 | 原因 |
| --- | --- | --- |
| 付费基础用户 | 默认不看 Admin | provider、模型、存储、额度由平台托管，用户应该直接创作 |
| 免费个人用户 | 看 Basic Admin | 用户需要自己填中转站 / provider key，跑通个人创作闭环 |
| 免费团队用户 | 看 Advanced Admin | 多人共享资源，需要治理、审计、用量、权限和高级路由 |

本地模式实际上就是免费个人用户的 Basic Admin。

它不追求“管理一切”，只追求：

```text
一个 key
一套推荐视频能力
一次可解释的验证
一个失败时能修的入口
```

### 1.2 免费个人的默认主路径

免费个人用户最常见的真实路径：

1. 用户买了一个中转站 / 聚合站 key。
2. 用户打开 MovScript，想生成视频。
3. 系统提示需要设置 Provider。
4. 用户粘贴 key。
5. 系统自动选择兼容 Provider 模板。
6. 系统应用“视频创作入门”能力包。
7. 系统验证文生视频是否可用。
8. 如果用户要图生视频，再提示配置素材中转或使用中转站支持的公网素材能力。

这条路径应该成为 Basic Admin 的第一路径，而不是隐藏在“高级 Provider 配置”里。

## 2. 本地模式导航

本地 / 免费个人模式只保留 5+1 个入口：

```text
开始
设置 Provider
能力状态
素材中转
任务诊断
高级
```

导航设计原则：

1. 不分复杂分组。
2. 不出现用户/组织/审计/治理。
3. 每个入口都有明确任务。
4. 如果有阻塞项，只在相关入口旁显示一个轻量状态点。
5. 高级入口放在最后，并弱化视觉重量。

## 3. 本地 / 免费个人标准路由

| 页面 | Route | 作用 |
| --- | --- | --- |
| 开始 | `/admin` 或 `/admin/v2` | 本地创作链路 readiness cockpit |
| 设置 Provider | `/admin/provider-setup` | 填 key、选择 provider、应用能力包 |
| 能力状态 | `/admin/capabilities` | 从能力视角看文本/图片/视频是否可用 |
| 素材中转 | `/admin/relay` | 配置 TOS / public relay，解决图生视频公网素材 URL |
| 任务诊断 | `/admin/diagnostics` | 解释最近失败任务，并给修复动作 |
| 高级 | `/admin/advanced` | 收纳 provider registry、catalog、route、logs、system |

### 3.1 付费用户不进入这些路由

付费基础用户默认从创作 Surface 和 Agent 进入 MovScript，不出现左侧 Admin 导航。只有在需要用户确认授权、额度或少量个人设置时，才打开 `/admin/focus/...`。

### 3.2 免费团队用户升级到完整后台

当 workspace 进入团队 profile，左侧导航从 Basic Admin 扩展为 Advanced Admin，并显示用户、组织、用量、审计、完整 Provider 和模型路由。

## 4. 页面 1：开始

### 4.1 页面目标

回答：

> 我现在能不能开始做视频？

### 4.2 首屏结构

本地开始页只需要四块：

1. **创作状态主卡**
   - 未配置：尚未接入 Provider
   - 部分可用：文生视频可用，图生视频待配置中转
   - 完整可用：视频创作链路已就绪

2. **链路检查**
   - Provider Key
   - 能力包
   - 素材中转
   - 本地存储
   - Worker
   - 测试生成

3. **下一步**
   - 最多 3 个动作
   - 必须能一键跳转

4. **能力摘要**
   - 文本与脚本
   - 图片与角色
   - 文生视频
   - 图生视频

### 4.3 空状态

空状态文案：

- 标题：还没有接入 Provider
- 说明：先添加一个 provider key，然后应用推荐能力包。
- 主按钮：设置 Provider
- 次按钮：打开高级

### 4.4 不显示

- 组织
- 审计
- 成本排行
- 全量日志
- route matrix
- raw JSON

## 5. 页面 2：设置 Provider

### 5.1 页面目标

回答：

> 我如何填一个中转站 / provider key，然后让系统自动具备可用的视频生成能力？

### 5.2 本地流程

本地流程应比完整快速设置更短，默认围绕“中转站 / 聚合站 key”：

1. 选择 Provider
2. 输入密钥
3. 选择能力包
4. 应用并验证

不需要单独的“目标”步骤，默认目标就是“开始做视频”。如果用户要其他目标，可以在能力包里选择。

### 5.3 Provider 选择

默认推荐：

- OpenAI 兼容聚合站 / 中转站
- 火山方舟官方 API

其他可选：

- 火山方舟代理/聚合
- 本地 OpenAI 兼容端点

Provider 卡片只展示：

- 适合场景
- 能力图标
- 是否推荐
- 是否需要素材中转

### 5.4 密钥输入

默认只显示：

- API Key
- Base URL（如果选择中转站则前置显示）
- 连接测试

高级折叠：

- Provider 名称
- Files API
- credential key

安全提示必须明确：

- Agent 不读取明文密钥。
- 密钥保存到本地加密存储。

### 5.5 能力包

本地默认展示三个：

1. **视频创作入门**
   - 文本规划
   - 图片生成
   - 文生视频
   - 图生视频预置

2. **完整多模态**
   - 视频创作入门
   - 图像编辑
   - 视频参考
   - 素材库

3. **仅 Provider**
   - 只保存 key
   - 不自动创建模型和线路

针对中转站 / 聚合站，能力包需要额外显示两类状态：

- 中转站声明支持的模型能力
- MovScript 已能映射到的能力

例如中转站 key 可以先启用文生视频；如果它没有文件上传或公网素材能力，则图生视频显示“待配置素材中转”。

### 5.6 应用结果

结果页不要展示内部对象列表，先展示：

- 已启用哪些能力
- 哪些能力仍需补齐前置条件
- 下一步建议

高级展开才展示：

- model template
- combo template
- public model id
- provider model id
- route group

## 6. 页面 3：能力状态

### 6.1 页面目标

回答：

> 当前文本、图片、视频、图生视频能不能用？

### 6.2 页面结构

能力状态页用“能力行”而不是卡片瀑布：

| 能力 | 状态 | Provider | 模型/线路 | 最近检查 | 操作 |
| --- | --- | --- | --- | --- | --- |
| 文本与脚本 | 可用 | 火山方舟 | text.default | 2 分钟前 | 测试 |
| 图片与角色 | 可用 | 火山方舟 | image.default | 2 分钟前 | 测试 |
| 文生视频 | 可用 | 火山方舟 | video.default | 2 分钟前 | 测试 |
| 图生视频 | 待补齐 | 火山方舟 | video.i2v | 缺素材中转 | 配置中转 |

点击能力行打开右侧详情：

- 当前状态
- 阻塞项
- 最近失败
- 推荐动作
- 高级入口

### 6.3 不显示

- priority
- capacity
- max concurrency
- pricing JSON
- route matrix

## 7. 页面 4：素材中转

### 7.1 页面目标

回答：

> 本地素材能不能被火山等 provider 访问？

### 7.2 为什么独立成页

对本地用户来说，素材中转是图生视频最关键、最容易失败、最难理解的前置条件。它不能藏在“资源与存储”的高级页面里。

对免费个人用户来说，素材中转有两种来源：

1. 中转站 / 聚合站本身提供可被 provider 访问的素材 URL。
2. MovScript 自己配置 TOS / public relay，把本地素材转成公网 URL。

页面应先判断用户是否已经通过中转站获得可用公网素材能力；只有缺失时，才引导用户配置 TOS。

### 7.3 页面结构

1. **状态主卡**
   - 未配置 / 可用 / 验证失败
   - 影响能力：图生视频、视频参考、素材库

2. **中转配置**
   - TOS Bucket
   - Region
   - Access Key ID
   - Secret Access Key
   - Public Base URL
   - Signing Secret

3. **验证步骤**
   - 上传测试文件
   - 检查公网访问
   - 检查 Provider 前置条件

4. **受影响能力**
   - 图生视频
   - 视频参考
   - Provider asset library

### 7.4 Agent 专注入口

如果任务失败原因是 `missing_public_input_url`，Agent 应打开：

```text
/admin/focus/storage.public_relay.configure
```

而不是让用户手动找素材中转页。

## 8. 页面 5：任务诊断

### 8.1 页面目标

回答：

> 刚才为什么失败？我下一步点哪里修？

### 8.2 页面结构

1. **最近失败**
   - 默认展示最近失败任务
   - 高亮最可能的阻塞原因

2. **任务列表**
   - 最近 20 条
   - 状态、类型、能力、Provider、错误摘要

3. **诊断面板**
   - 用户可读解释
   - 证据检查
   - 推荐动作

4. **高级详情折叠**
   - provider request/response
   - provider task id
   - route selection
   - raw error

### 8.3 修复动作

常见动作：

- 设置 Provider
- 应用能力包
- 配置素材中转
- 打开 Agent 专注修复
- 查看高级线路
- 重试任务

## 9. 页面 6：高级

### 9.1 页面目标

回答：

> 我确实知道自己要改内部机制，入口在哪里？

高级页是本地模式对完整后台能力的收纳区。

### 9.2 标签

建议：

- Provider 详情
- 模型与路由
- 参数与成本
- 存储详情
- 日志与调用
- 系统设置

### 9.3 视觉原则

- 高级入口弱化，不抢本地主流程。
- 进入后可以高密度。
- 每个标签顶部提示：“通常不需要修改这里”。
- 从诊断或 Agent focus 跳入时，自动定位相关实体。

## 10. Agent 专注模式在本地模式中的角色

本地模式下，Agent 专注模式是“精准修复弹道”，不是另一个后台。

常用 focus：

| Focus | 何时打开 | 用户需要做什么 |
| --- | --- | --- |
| `setup.video.start` | 空系统或缺 provider | 输入 key，确认应用能力包 |
| `storage.public_relay.configure` | 图生视频缺公网 URL | 填 TOS，验证中转 |
| `job.failure.triage` | 生成失败 | 看解释，选择修复动作 |
| `capability.test` | 用户想验证能力 | 确认测试 |

专注模式要点：

- 没有完整左侧导航。
- 显示 Agent 计划栏。
- 显示证据面板。
- 密钥由用户输入。
- 高风险动作由用户确认。
- 完成后回到 Agent thread 或本地页面。

## 11. 本地模式视觉方向

关键词：

- small local control room
- personal setup center
- calm and practical
- no platform noise
- obvious next action

视觉约束：

- 不用平台级仪表盘大网格。
- 不用组织/审计/租户语言。
- 不用营销 hero。
- 不用装饰性图形。
- 状态和行动优先。
- 复杂机制放进高级。

## 12. 本地模式第一版验收标准

1. 空系统时用户只看到“设置 Provider”作为主路径。
2. 火山 key 用户能在一个流程里完成 provider + 能力包。
3. 首页能明确显示文生视频是否可用。
4. 图生视频缺素材中转时，不阻塞文生视频。
5. 素材中转有独立入口和 Agent focus。
6. 失败任务能给出用户可读解释和修复动作。
7. 高级能力存在，但不污染本地默认导航。
