# MovScript Agent Observability

The local agent exposes three observability layers:

- Metrics: `GET /metrics` returns Prometheus text format generated by `prom-client`.
- Trace: `GET /runtime/telemetry` returns the in-memory operation window plus trace-derived spans for model calls, tool calls, approvals, inputs, context, and run lifecycle work.
- Logs: slow and failed operations/spans are retained as structured diagnostic log entries in the same runtime telemetry snapshot.

The runtime snapshot is intentionally a short local window. Long-term aggregation should be Prometheus/Grafana or an OpenTelemetry backend, not the frontend console or `agentPerformanceStore`.

## Local Stack

Start the agent locally:

```bash
pnpm --filter @movscript/agent dev
```

Start the local observability stack:

```bash
docker compose -f apps/agent/observability/docker-compose.yml up -d
```

Ports:

- Prometheus: `http://127.0.0.1:9090`
- Grafana: `http://127.0.0.1:3001`
- Tempo: `http://127.0.0.1:3200`
- Loki: `http://127.0.0.1:3100`
- OpenTelemetry Collector OTLP: `http://127.0.0.1:4318` and `grpc://127.0.0.1:4317`

## Prometheus

Run Prometheus with the sample config:

```bash
docker run --rm -p 9090:9090 \
  -v "$(pwd)/apps/agent/observability/prometheus.yml:/etc/prometheus/prometheus.yml:ro" \
  prom/prometheus:v2.55.1
```

On macOS and Windows Docker Desktop, the sample target `host.docker.internal:28765` reaches the local agent. On native Linux, replace the target with the host address that can reach the agent port.

Useful first queries:

```promql
movscript_agent_operation_duration_ms{quantile="0.95"}
movscript_agent_trace_span_duration_ms{quantile="0.95"}
movscript_agent_operation_active
movscript_agent_slow_operation_total
movscript_agent_error_trace_span_total
```

## Grafana

Import `grafana-dashboard-agent.json` and point its Prometheus datasource at the Prometheus instance above. The dashboard is deliberately small: latency, pressure, trace mix, and trace health.

## OpenTelemetry

`otel-collector.yml` is the standard external entry point:

- Metrics pipeline scrapes `GET /metrics` from the local agent.
- Trace pipeline receives OTLP and exports to Tempo.
- Log pipeline receives OTLP and exports to Loki.

Configure the agent to emit OTLP traces/logs:

```bash
MOVSCRIPT_AGENT_OTLP_ENDPOINT=http://127.0.0.1:4318 pnpm --filter @movscript/agent dev
```

The frontend console remains the first-pass local diagnostic surface, while Prometheus/Grafana/Tempo/Loki handle long-term aggregation and deeper analysis.

## Dependency

The agent declares `prom-client` as a required dependency. If it is missing, typecheck and startup should fail early instead of silently degrading metrics output.
